🔄 Guía de Restauración del Sistema
Pasos para recuperar el sistema en caso de falla o cambio de equipo
🕓
Backup automático activo El sistema crea una copia de seguridad cifrada de lunes a viernes a las 4:00 PM en Google Drive. Se conservan los últimos 30 backups. Restauración probada con éxito el 2026-09-24.
📌 Esta página no estará disponible si el servidor se daña. La guía completa (plan de continuidad) está también en GitHub: RESTAURACION.md en github.com/jdbarajass/SDS_OCDI.
🔐 Guardar HOY fuera del servidor
  • Contraseña de cifrado de los backups (archivo data\backup_password.key del servidor). Sin ella ningún backup se puede abrir y no hay forma de recuperarla. Guárdala en un gestor de contraseñas y en un sobre sellado en poder de la jefatura. No la guardes en la misma carpeta de Drive de los backups.
  • Acceso a la cuenta de Google donde está la carpeta de backups.
  • Contraseña del usuario Admin de la plataforma (se restaura con el backup, pero hay que conocerla).
0 Requisitos previos (instalar en el PC nuevo)
  • Python 3.10 o superior, en python.org/downloads. Marca ✅ "Add Python to PATH" durante la instalación
  • Git, en git-scm.com/download/win
  • Google Drive para escritorio, en drive.google.com/drive/download. Inicia sesión con la cuenta de los backups para que monte la unidad G:
1 Obtener el código fuente
cd C:\ git clone https://github.com/jdbarajass/SDS_OCDI.git cd SDS_OCDI

Si la red de la oficina bloquea GitHub, hazlo desde otra red o usa Code → Download ZIP en github.com.

2 Instalar dependencias
pip install -r requirements.txt
3 Restaurar los datos (automático)
python restaurar_backup.py

Toma el ZIP más reciente de esta carpeta de Google Drive, pide la contraseña de cifrado, deja la base de datos en data\ocdi.db, guarda la contraseña para los backups siguientes y comprueba que la aplicación arranca. Debe terminar con ✅ RESTAURACIÓN COMPLETA.

🔒 Restauración manual (sin el script): abre el ZIP con 7-Zip o WinRAR (el explorador de Windows no abre AES-256) usando la contraseña. Copia ocdi.db a SDS_OCDI\data\ocdi.db y crea data\backup_password.key con la contraseña como único contenido. Para restaurar un ZIP concreto: python restaurar_backup.py "ruta\al\archivo.zip"
4 Arrancar el servidor y dar acceso a la red
  • Doble clic en iniciar.bat. No cierres la ventana negra.
  • Abre http://localhost:8000 y entra con tu usuario de siempre.
  • ipconfig → anota la Dirección IPv4 y avisa a todos: http://<IP-nueva>:8000
  • Abre el puerto en el firewall (cmd como administrador):
netsh advfirewall firewall add rule name="OCDI 8000" dir=in action=allow protocol=TCP localport=8000
5 Reactivar el backup automático (obligatorio)
  • Si Google Drive quedó en otra ruta: setx OCDI_BACKUP_DIR "G:\...\Backup_Automatico_OCDI"
  • Doble clic en configurar_tarea_backup.bat (como administrador si falla)
  • Verifica que la tarea exista: schtasks /query /tn "OCDI_Backup_Diario" /v /fo list
  • Fuerza una ejecución: schtasks /run /tn "OCDI_Backup_Diario" → debe aparecer un ZIP nuevo y una línea OK en backup_log.txt
🧪 Simulacro mensual (recomendado)

Prueba que el último backup sí restaura todo, sin tocar el sistema en uso. Desde la carpeta del proyecto en el servidor:

python restaurar_backup.py --simulacro

Resultado esperado: ✅ SIMULACRO EXITOSO. Queda registrado en simulacros_log.txt de la carpeta de backups.

🔑 Credenciales de acceso

Los usuarios y sus contraseñas están dentro del backup (ocdi.db) y se restauran automáticamente. No existe una contraseña por defecto. Solo si se arranca sin ningún backup, el sistema crea los usuarios iniciales con contraseñas aleatorias guardadas en data\seed_passwords_iniciales.txt (o las de las variables OCDI_SEED_PWD_*).
